# Proxy Tunnel Desktop

Прототип приложения для Windows x64 с личным VPS. Базовая версия исходников — 0.1.10. Интерфейс на русском языке.

Приложение подготавливает сервер Ubuntu/Debian по SSH и использует sing-box для зашифрованного транспорта, полного или выборочного маршрута. Есть журнал, отчёты ПК + VPS, автозагрузка при входе в Windows и kill switch. Приложение запрашивает права администратора для сетевых настроек. Автозагрузка сама не подключает туннель.

## Состав

- `src/ProxyTunnel/` — исходники приложения, установочный скрипт сервера и проверки.
- `observer/` — отдельный подготовленный наблюдатель VPS, инструкция, контрольные суммы и тесты. Приложение не устанавливает его автоматически.
- `licenses/` — уведомления о лицензиях компонентов.

Личные настройки, IP сервера, ключи, журналы, зависимости и готовые EXE в репозитории отсутствуют. Папка не содержит истории прежних рабочих каталогов.

## Сборка

На Windows x64 установите .NET 8 SDK. В PowerShell из корня репозитория:

```powershell
./src/ProxyTunnel/build.ps1
```

Скрипт скачивает официальные архивы sing-box 1.14.4 для Windows/Linux, проверяет фиксированные SHA256 и восстанавливает зависимости NuGet. Результат: `src/ProxyTunnel/publish/ProxyTunnel-Prototype.exe`. Компоненты и SDK-кэш находятся в игнорируемой папке `src/tools/`. Не загружайте их в Git. Для офлайн-проверки исходников можно явно указать каталог уже проверенных компонентов свойством MSBuild `ProxyTunnelToolsRoot`.

## Настройка и ограничения

Введите адрес собственного VPS, SSH-порт и доступ администратора на странице «Сервер». Ключ SSH-сервера необходимо проверить при первом подключении. Данные подключения хранятся локально, секрет транспорта защищён Windows DPAPI. Пароль подготовки VPS не сохраняется приложением.

Приложение меняет сетевые настройки Windows; при активном kill switch интернет может остаться заблокированным после сбоя. Штатное отключение защиты доступно в интерфейсе; аварийная команда находится рядом с исходниками. Проверки намеренных обрывов с реальным TUN/WFP ещё не завершены. Защита WSL и виртуальных машин отдельно не подтверждена. Используйте с учётом этих ограничений.

История ПК хранится один календарный месяц, экран показывает последние 24 часа. Отправляемые отчёты могут содержать IP и технические сведения: проверьте их перед публикацией. Никогда не добавляйте личные отчёты в публичные issues или исходники.

## Обновления

В 0.1.10 в настройках добавлена кнопка «Проверить обновления». Источник закреплён: GitHub Releases этого репозитория. Загрузка выполняется через VPS, манифест проверяется закреплённым открытым ключом ECDSA. Отдельный установщик сохраняет старый EXE и выполняет замену под блокировкой, затем запускает восстановление туннеля. Подробности, формат выпусков и ограничения: [UPDATES.md](UPDATES.md).

Первое обновление с 0.1.9 выполняется вручную: она не содержит механизма обновления. Для дальнейшей загрузки нужны подписанные Releases с большим номером. Код обновления реализован, но реальное обновление с активным TUN/WFP ещё не испытано. Намеренные обрывы на рабочем ПК не тестировались. Это прототип, а не гарантия отсутствия утечек.

`release-tools/ReleaseSigner` — инструмент владельца для упаковки и подписи; закрытый ключ не поставляется и не должен добавляться в репозиторий. Файл `update-public-key.pem` содержит только открытый ключ проверки.

## Проверки

Проверки C# встроены в проект: `--update-test`, `--self-test`, `--log-period-test`, `--vps-log-test`, `--reports-test`, `--stability-test`. Их запускают в отдельном тестовом каталоге с `PROXY_TUNNEL_TEST_DATA`, через собранную DLL. Не запускайте `--privacy-test` на рабочем компьютере: он предназначен для испытаний защиты. Сетевые тесты требуют сети. Для проверки TCP до собственного VPS вручную задайте `PROXY_TUNNEL_VPS_TEST_HOST`; адрес сервера в исходниках не зашит.

Тесты наблюдателя: `python -B -m unittest discover -s observer -p 'test_*.py'`. Они используют временные каталоги и подставные ответы systemd и не устанавливают службу.
